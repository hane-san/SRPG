# 全員本城待機→出撃演出　試遊メモ（Issue #29）

> **試作中・PR #31／未マージ。** P3専門職化PR #27のブランチをベースとするStacked PRで、通常の公開mainとは異なる。

## 何を見たいか
兵が最初から盤面に並んでいるのではなく、城にいる人物を指揮官が選び出撃させる手応え。城から現れる「ガチャン、ガチャン」の金属音と短い一言が、操作を邪魔せず気持ちよいか。

## 新しい出撃の流れ
1. 味方は全員本城の予備で開始。盤面には味方0隊。
2. 城のマスをタップ（またはドックの出撃ボタン）。兵種アイコン＋名前で1隊を選択する。
3. 城から合法マスへドラッグし、空きマスで指を離すと移動＋待機で出撃確定。通常のタップ・手動「攻撃／待機」も残す。攻撃対象を指定した場合は通常の攻撃命令で確定。
4. 確定後、城のマスで兵が姿を現す。短い金属音2打→「出撃する！」の吹き出し→指定経路移動→必要なら攻撃/反撃。
5. キャンセル・不正な移動先・誤った対象では出撃枠、予備、戦闘状態、保存は変わらない。演出は再生のみで戦闘処理を変えない。

- 初ターンだけ2隊まで、以後毎ターン1隊。戦場同時最大5隊。初手で城に待機する場合は2隊目の出撃先が占有状態にならないよう注意。
- P3専門職（砲兵・魔術師系）は城から移動したターンにP3行動をしない。城のマスから動かず待機した時は静止扱い。
- セリフは全員共通「出撃する！」の字幕のみ。個別・ランダム・特殊条件や音声は追加せず保留。
- 高速モードは演出を短縮、Reduced Motionでは出現を簡略化。SE OFFでも成立する。

## 検証
- 6マップ、320/360/390/844px、縦/横。最初に味方0、予備全員の状態で城が分かりやすいこと。
- 初ターン：1隊目出撃後にもう1隊を出撃できる。3隊目は不可。次ターンに1隊可能。城に誰かが立つ場合のタップ優先、帰還・再出撃、最大5隊も確認。
- 選択だけ→Escape・空きマスへドラッグ途中の取消・不正対象・射程・天候/森林移動コスト。状態/出撃枠/セーブは不変。
- 出撃→移動→攻撃/反撃までの描画順。短い出撃台詞が盤面を遮らないか。戦闘音・BGM・無音・高速で二重操作を防ぐ。
- リロード/途中セーブ、敵行動とP3/P4、全滅判定、城陥落判定、連戦への引継ぎを回帰。
- iPhone実機でスライドが指に吸い付くか、SEの2打が大きすぎないか、字幕が短すぎないかを判断。

## 想定される副作用
- 城が開幕から無人になることで敵の強襲への対応が遅れる可能性。ただし初ターン2隊出せるため元の投入量を近似。戦術として「初手どの2隊を選ぶか」に意味が生まれる。
- 城の操作と通常のユニット選択が競合する場合は城タップを優先。城上のユニット選択は部隊表経由でも可能。
- P3専門職・移動/Undo PR #25と重なる app/ui-input/playback/render 等は、統合時に別途リベース・独立監査。現時点でmainへは入れない。

## 受入・責任区分
Issue→PR→rules/browser CI→別の実装者による独立監査→プロデューサーの試遊・採用判断→main。自分が実装したコードの簡易テストは独立監査ではない。CIだけで面白さを採用しない。
