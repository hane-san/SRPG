## 同一方策の比較

`npm run audit:issue17`。毎ターン、予備を編成順に1隊だけ選択し、城を起点とする通常移動＋攻撃/待機で出撃する。盤面5隊上限を維持。前進策は攻撃・危険・目標距離の決定論評価。本陣がある場合の盾は本陣占有を優先し、回復隊は負傷者へ近づく。この方策と定数を前後の両配置へ同一適用する。
全待機策は既存隊をその場で待機させ、新規出撃は城または最小コストの空きへ移動待機。40ターン上限、6ターン盤面が不変なら早期停止。攻撃回数はP2の実observerから計数し、予測危険値ではない。

- 出撃/防御/撃破/命中のオフライン波形は全サンプル有限、4種類が異なり無音なし。ピーク約0.055/0.083/0.097/0.230、0.6秒以降の残響0、クリッピングなし。ミュート保存と、SEをONにしたままAudioContext生成が失敗しても同じ戦闘結果へ続行することを確認。
- 移動65ms/マス、部隊前後の間60ms/25ms。命中と反撃の表示時間・順番は維持。空フェーズは長いphase pauseを省き、結果がある場合のみ短く表示する。ゲームのフェーズ自体は省略しない。

ローカルの通常Chromiumダウンロードとgit cloneはネットワーク経路が失敗したため、GitHub接続で特定SHAの内容を取得し、npm配布のChromiumを一時使用。CIは既存のNode22 / Playwright1.57.0 Chromiumを使う。GitHub上の確定SHA・独立監査・CI結果はPR本文に記録する。
