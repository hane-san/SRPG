# v0.6.0 — テンポ・配置・フェーズ音楽の監査

2026-10-18（日本時間）。比較元は main `8941f5002e9d2b19bb4e8a34de65ee3d9e25ae0c`（v0.5.2）。途中保存の部隊は保ち、新しい初期配置と敵の耐久は新規開始／再試行で適用する。

## 変更前に分かったこと

- 攻撃／待機の一押し実行は既存。通常の命令に別の確定操作を足す必要はない。結果が小さな吹き出しと盤面の数字に散り、画面外の攻撃を追いにくかった。
- 初接触は前進の6例ともT1。一般兵の高い耐久、守備役が本陣の下にいた配置、長いマップの均等な敵列が、前進の停滞と初見の本陣陥落に結びついていた。
- 永久離脱者を除いてから配置番号を振る実装により、他の専門役まで前詰めになっていた。

| `data.js` | 初期兵・増援とも一般兵HP14〜18、剣/弓/騎兵の守備を3/2/3、盾5に調整。守将HP22・守備5。味方の基本能力とシューターHP10は維持。第2章は本陣の守備＋隣接回復と東の騎兵。南増援はT4/8/12各1、南城で停止。第3章はT4/8各1。追加戦場は前衛・援護・側面・城門を手配置。敵IDは安定維持。 |

## 音楽の設計

任天堂の[開発者インタビュー](https://www.nintendo.com/au/news-and-articles/ask-the-developer-vol-8-fire-emblem-engage-chapter-1/)では、地域ごとにデザインと音楽の違いを付ける考え方が説明されている。ここではその考え方を、戦場ごとの音色とフェーズごとの緊張の差として解釈した。旋律・音源はこのゲーム用に作成した。

| 戦場 | P1 | P2〜P4 | 音色・拍感 |
|---|---|---|---|
| 霧河 | 川霧を越えて | 霧中の足音 | 笛とハープ、三拍子 |
| 二戦線 | 守り継ぐ旗 | 挟撃の鼓動 | 弦と低音、行進感 |
| 灰城 | 灰を裂く光 | 城壁の残響 | 金管風と低い和音 |
| 三橋 | 三つの橋の旅路 | 流れを塞ぐ槍 | 明るい笛、流れのある分散和音 |
| 雨森 | 木洩れ雨の回廊 | 雨幕の追跡 | ハープ、控えめな笛 |
| 暁城 | 暁の城塞へ | 最後の防壁 | 金管風、前進感と緊張 |

各約49〜69秒の32小節ループ。第3の反復で高音の変化、別の反復で対旋律を加える。BGMは効果音より抑え、切替時は短くフェードし、先読みで連続再生する。合成音楽の試作であり、生演奏のオーケストラ録音ではない。

## 検証と残る課題

- `npm run check`：ルール・保存・配置・音楽モデル、永久離脱を伴う連戦の54試験成功。
- 全6マップ×4画面、予告有無×5画面、320pxの複数対象と離脱警告、タッチの経路保持・取消・パン・二重実行防止。
- 通常速度で移動の中間座標、最初の命中→反撃の別々のHP、画面外でも読める固定欄を採取。1ボタン実行と結果の閉じる操作なしを確認。
- 最大BGM音量で12曲をOfflineAudioContextで全長生成し、異常値・無音・波形の同一化・クリッピングを検査。初期OFF、独立音量、P2〜4の継続、再読込、ミュート後の予約停止も確認。

貪欲な自動方策は人間の楽しさや最適解を証明しない。第2章の慎重策は危険を避けて本陣を放棄しT15敗北、第4章の慎重策はT35で停滞する。P3が少ない第3章の選択価値、同じ位置での回復待ち、挑戦難度は引き続き検討対象。時間圧力のない戦場に一律の制限ターンは入れていない。

手元はChromiumのタッチ・画面模擬。iOS Safari/Android実機の操作感や端末スピーカーでの聴感は未検証。小さい横画面では固定欄と盤面の広さの両立が今後の確認点。通常の攻撃・待機に余分な確認を入れずに改善する。

手元の7スイートは個別実行で全て成功。結果・54試験・最大音量の波形統計は [QA記録](qa-results-0.6.0.json)。公開前にGitHub Actionsで全体を実行する。
