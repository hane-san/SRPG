# 次の開発で見ること

方向性：GBA時代のSRPGの素早い選択・見通せる戦闘・読みやすい盤面と、
現代的なタッチ操作・明示確認・自動保存を両立する。オリジナルの4フェーズと
動かず待機するP3支援を軸にする。FEの画像・音・キャラクターは使わない。

## 0.5.1で追加したこと

- 描いた矢印の終点を、後から敵へフリックしても維持。射程外でも勝手に移動先を変更しない。
- 移動先のそばに指示矢印付きの命令窓。青い移動範囲・外周と、その外の赤い攻撃可能域。
- 短い打撃・金属音を重ねた攻撃音。
- 検証は [destination-0.5.1.md](destination-0.5.1.md)。

## 0.5.0で追加したこと

- 下部ツールの折りたたみ・常設案内の除去・選択元/移動先/対象を避ける半透明窓。
- 兵種の形と記号、弓の射程説明と矢の飛翔、兵種別効果音、通常速度の読み取り時間。
- シューター、雨の森の移動減少周期とマップ別色調。
- P3に隣接する味方全員を回復。何人でも1ターンの発動で1回分だけ消費。
- 単体用の追加戦場04〜06。既存3章の連戦は維持。
- 検証とCI失敗原因は [readability-0.5.0.md](readability-0.5.0.md)。

## 0.4.0で追加したこと

- 押下からの連続スライド、敵までつなげる経路、離したら攻撃・待機・戻るの直接3択。
- タイル間移動、攻撃→反撃、敵一隊ずつの進行、効果音と永続ミュート。
- 半透明メニュー、長押し抑止、独自パン、端の自動スクロール、演出中の再読込保護。

## 0.3.0で対応したこと

- 攻撃前の双方の残HP、撃破・反撃による離脱、移動先の地形守備を表示。
- 攻撃ボタンで射程内対象を巡回。次の未行動部隊と未行動数を追加。
- キー操作と段階的な取消。一隊ずつの敵・支援再生、高速設定。
- 戦場を変える前の確認、0.2.0の保存移行と破損保存の検証。
- 仮アプリアイコン、GPT/Claude共通の開発契約と検証手順。

## 優先する追加検証

1. **実機の操作感**：iOS Safari/Android Chromeで小さい移動マスの押し間違い、
   命令ウィンドウによる遮蔽、横持ちの予告あり状態を測る。Chromium模擬とは分ける。
2. **盤面の読み取り**：画面外の敵行動や複数ダメージの経緯は記録が必要。
   カメラを勝手に動かさず、結果を追える表示を比較する。
3. **第2章の初見難度**：本陣留守番・東道・南城の別解を実プレイで検証。
   貪欲方策の勝敗は人間の楽しさや最適戦略の証明ではない。
4. **P3攻撃の使いどころ**：停止する価値と有限回数の消費を、敵配置・通路で比較。
   新しい状態や敵P3を増やす前にマップで調整する。
5. **説明の量**：P3準備中の反撃放棄、対象なしの消費0、応急回復の上限が伝わるか。

成長・装備・物語は未実装。効果音は0.4.0から実装済み。命中乱数、必殺、追撃、属性相性を追加する場合は、
現行の決定論と予測表示を含めて別の設計判断として扱う。
