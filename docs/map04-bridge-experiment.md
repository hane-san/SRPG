# マップ04「長河の三橋」 橋頭戦の段階化試験（Issue #38）

2026-10-22。縦40マスの二河川・各三橋マップで、敵全軍がT1から詰め寄る配置を、**橋の手前／対岸を守る二段構え**へ変更する小さな可遊試作。地形は変えず、配置だけで効果を比較する。次の段階で距離・橋幅・マップ寸法を再検討する。

## 事前の仮説
現行の04は開幕で3回の敵攻撃が集中する上、初動で前衛を失って長距離前進が消耗戦になり、先に渡河地点を選ぶ余裕が乏しい。最初の接敵を「敵の待つ渡しに進軍する」に変えれば、橋を選ぶこと自体が戦術になる。

## 変更
- 最初の敵前衛・盾 `extra-3-0-0` を (6,29) advance → **(6,24) defend**。第一河川の北側（橋の出口）を守る。
- 最初の敵騎兵 `extra-3-0-3` を (9,27) advance → **(9,22) defend**。東の渡河先を守る。
- 残りの弓・剣は南側の先触れのまま、ほか9隊は全く移動しない。敵数13、味方11、HP6/AI計算式/4フェーズ/P3、橋・河・街道・砦と全タイル、寸法12×40、勝利・保存条件を維持。
- 敵の初期マスで地形を`=`に上書きする従来生成処理を保ち、**地形生成の後で敵仕様だけ移動**。以前の地形・途中セーブが変わらないようにする。
- ブリーフィングだけ、南側先触れと北側橋頭守備の違いを説明。

```
北城
    北側の第2前線（変更なし）

  [盾・橋北]        [騎兵・東道守備]  ← 今回はここで迎え撃つ
━━━━━━━━ 第1河川 ━━━━━━━━
  [弓]  [剣]                 ← 南の先触れを迎撃して渡河路を選ぶ

味方の本城（全員予備から出撃）
```

## 決定論の比較試験（実行済み）
GitHub mainの `config.js` / `data.js` / `engine.js` / `tests/simulate.mjs` / `tests/tactical-observer.mjs` から関数単位のV8再生。標準難易度・同じ出撃ルール・同一方策、40ターンまで。**正式なNode/ブラウザCIや人間による遊びやすさ試験ではない**。

| 固定方策 | 改修前 | 試作 |
| --- | --- | --- |
| 通常前進 | T40実行後も未決着、味方離脱8 | **T25勝利、離脱2** |
| 慎重前進 | T40実行後も未決着、離脱3 | **T27勝利、離脱2** |
| 速度優先・P3なし | T32敗北、離脱11 | **T26勝利、離脱1** |
| 開幕の敵通常攻撃（通常前進） | T1に3回 | **T1に0回** |
| 通常前進の無交戦ターン | 18 / 40 | **5 / 25** |
| 通常前進のP3実発動 | 6 | **4** |

**読み取り**：第1ターンに盾と騎兵が突出するのを抑え、敵が橋を守ることで進撃と反撃の差が出た。速度優先でも勝てるようになった一方、一般兵主体など別の方策は依然として停滞する。三橋がそれぞれどの程度役割の違う通路として使われたか、人間試遊は未確認。

### 採らなかった試案
- 単に盾／騎兵のAIだけを`defend`に変更：T1の集中は2回に減るがT34でも未決着・離脱8。
- 第1線を一律2〜4マス北へ下げる：T1攻撃は0回でもその後の全滅や停滞が起きる案がある。
- 騎兵だけ北へ2マス：前進はT34未決着・離脱3。守備の位相を同時に変えることが有効だった。
- 橋数を減らす／地形を一気に全面改修：新しい地形が良いかは別の比較を要するため、本PRでは保留。

## 人間の試遊
1. 開幕、南側の先触れに慌てず対応できるか。盾・弓・騎兵の出撃順で戦い方が変わるか。
2. 一つ目の河川で左右・中央のどの橋を使うか迷えるか。橋の出口にいる盾・騎兵を正面から崩す／迂回する意味があるか。
3. 二本目の河川まで単なる作業移動にならないか。盤面の縦スクロール、部隊ごとの経路操作負荷をiPhone実機で確認する。
4. 遅い試行も別解として成立するか。AIで勝利を確認したことと楽しさの判定は区別する。
