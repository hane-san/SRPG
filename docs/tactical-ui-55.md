# 戦場UI第2弾 — 先読み・因果・親指の操作設計

## 確定・採用した方向性（2026-10-22 21:46）
プロデューサーから「小糸ちゃんセンスで徹底的に考えて入れておいて」と委任された範囲のUI改善。試遊できる最小単位として、**見えている危険・攻撃で起きた事実・親指の到達性**の3つを優先。

- プレイヤーの**一手に意味**があるようにする。敵予測はその場で分かる。ただし「敵全員がそこを狙ってくる」といった嘘は表示しない。
- 結晶は1個=HP1。反撃や盾の防御、残HP以上の攻撃では**実際に増減したHPだけ**で破砕と再生を説明。
- 片手プレイの切替でカメラやマップ、タイル/攻撃の判定が変わってはいけない。
- 情報の追加は既存の**固定144px縦 / 300px横ドック**内。追加モーダルや常時全画面オーバーレイなし。

## 実装・受入
1. **P2リスク**：`E.threatAt`をそのまま使い、各敵が自分だけそこへ到達・攻撃できるかを独立判定して実被害の合算を出す。この数は高めの危険目安で、実際の敵AIによる攻撃指示・相互進路競合・味方の反撃・他部隊による敵撃破は考慮しない。本文では「P2射程概算」「確定被害ではありません」と明記。0/1-2/3+/現在HP以上で警告の濃さを変える。予告済みP4砲撃セルは別警告。
2. **性能**：`app.js`内のMap cacheは現在状態オブジェクトとターンをキーに破棄、個別のunitID/HP/移動マスで値を再利用（最大128件）。プレイバック中には呼ばない。状態変化の直後に古い値を読むことを防ぐ。
3. **戦闘因果**：`presentCombat(before,after,event,stage)`の確定イベント状態から実HP差を計算。通常攻撃・反撃・回復、盾の防御、強いオーバーキルを区別。ダメージ判定やセーブに関与させない。`combatCue`は純粋な表示モデルのみ。
4. **親指モード**：現在の左マップツール/右UNDOを既定「右」にし、「左」ならそれぞれ左右入替。リロード後も`field-command-thumb-side`独立設定で維持。メニュー/ヘッダー/ドック/ワールドカメラ/保存キー不変。スクリーンリーダーの戦場ラベルも左右を伝える。
5. **スマホUI**：表示は1行の`.route-risk`、必要ならトランケーションで既存ドックからはみ出さない。詳細はドラッグのテキストとユニットの能力情報を維持。効果音ON/OFFと低減モードに関係なく文字でわかる。
