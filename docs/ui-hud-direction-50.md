# 戦場UIの全体見直し／Issue #50 第1弾（2026-10-22）

## 決定された方向性と実装済み
プロデューサー：「戦闘の感触を改善してきたのでUIもアップグレード。できることは進める」。この実装は**戦術判断とタッチテンポを優先する、情報の視覚的階層化**の小さな一歩。現行mainの読み込みを基準に、実際の変更をIssue #50およびPRに記録。

| 見る状況 | 旧状態 | 第1弾 | 受入 |
|---|---|---|---|
| 現在フェーズ | 文字「味方/敵軍/支援/戦場」だけ | ヘッダー下に4区画の細い進行レール。現区画の明るさ・過去区画の濃度で進行を把握 | P1〜4の対応、勝敗後の非活性、aria-current |
| P4の予告 | 同一色に天候・砲撃・増援を混在 | 砲撃=赤茶警戒、増援=紫、天候=穏やかな灰青 | 複数があると砲撃を優先。詳細な文字は残す |
| HP6 | 半端な連続バー | バーには6等分の濃淡の目盛り、実HP数値そのまま | 6粒の破砕との意味の統一、セーブ/戦闘計算不変 |
| フリック中の情報 | 移動/敵/不正が文字だけで近い | 攻撃=琥珀、固定=薄緑、エラー=赤の控えめな縁色。数値と文言も存続 | 命令欄144px、地図スクロール・Undo・タップ/キーボード保持 |
| 移動・ターン継続 | ボタン密集 | 次の未行動部隊の控えめな強調と、フォーカス表示を維持 | タップ域44px以上。未行動があるとき終端を押させる設計は追加しない |

**視覚は戦術に従属する。** 文字と数値を残し、色覚や音に依存させない。演出用の表示変更で`engine.js`/`save.js`に触らない。見た目の派手さだけの機能を増やさず、地図・駒・攻撃経路の視認性を保つ。

## 非採用・今後の提案（勝手に実装しない）
- **提案：敵の行動予測の焦点表示**：1ユニットごとの移動後攻撃可能マス・P2予想被害をスマホの指位置近くに素早く出す。読み間違いとパフォーマンスのリスクがありゲーム試遊で判断。
- **提案：片手モード**：利き手に応じてUNDO/マップツールを左右へ配置。iPhoneでの実際の指移動距離データが必要。
- **提案：戦闘報告の因果表示**：攻撃→軽減→反撃を1行で明確化。ユーザーが演出を楽しみながらも数字を読めるかで調整。
- **提案：予告が重なったときの折りたたみ**：砲撃・増援・天候を一段で優先度順に見せ、詳細タップで展開。発火数が少ないマップでは過剰UIになりうる。
- **提案：ユニットスプライトの全面更新**：世界観の方向性確定とマップレイアウト調整の後。今はPR #36/#45/#49の戦闘モーションの統合が先。
