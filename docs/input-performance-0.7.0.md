# v0.7.0 — 入力・描画負荷・拡張前の監査

比較元は main `69c72318d3cf3aabc011807311cdf3ba054fa848`（v0.6.0）。先行して追加された6マップ・雨・範囲回復・シューター・戦闘結果欄・12曲BGMを保った上で修正した。戦闘数値・配置は今回変更していない。

## タップとスライド

| 操作 | 結果 |
|---|---|
| 未選択の味方をタップ | 選択。その場の攻撃／待機も直接選べる |
| 選択後、合法な空きマスをタップ（その地点から攻撃できる敵なし） | 移動＋通常待機を即実行。余分な確認なし |
| 攻撃できる移動先を押す | その地点を仮の終点として保持。敵へ滑らせる |
| 敵を選ばず離す | 押す前の選択・経路に戻る。移動・消費なし |
| 敵まで滑らせて離す | 終点を保って予測表示。攻撃を一押しで実行 |
| 選択中の本人、移動できない空きマスをタップ | 選択を取り消す |
| 部隊から移動先へドラッグ | 従来どおり攻撃／待機／戻る。攻撃できる場所で攻撃せず待機したい場合にも使う |
| 既に描いた矢印から再び敵へフリック | 既存の終点と経路を保持。射程外でも自動で射撃地点を変えない |

押している途中は命令欄を隠す。別の部隊・メニューへの操作やキーボード命令も抑止し、入力の途中で選択部隊だけが変わる競合を防ぐ。pointercancel・複数指・長押し・端スクロールの契約を維持。攻撃前に予測を読める一押しを残し、指を離した瞬間の誤攻撃を避ける。キー操作は従来の矢印／Enter／A／W／Esc／N。

## 見つけて直した箇所

- 地形の細部・危険域の探索・移動／通常攻撃範囲・発光外周を、演出の全フレームで再計算していた。`render.js` を地形・戦術背景・動く部隊の層へ分離。地形と戦術背景はCanvasごとに各1枚、32px/マスで保持する。現在最大面積の14×44で両面約4.8MiB、画面用canvasは別。古いcanvasはWeakMapのため常駐リストに残さない。
- キーには盤面内容、天候、位置・生死・移動・射程・兵種、選択、予告、移動先などを含め、同じ状態の演出だけ再利用する。地形を直接編集しても古い表示が残らない。範囲の変更とHPだけの変更を分け、HPバー等は毎フレーム正しい部隊データから描く。
- 同じマス内のpointermoveで経路を何度も再計算しない。経路探索の占有判定は探索中のMapへ、単発の占有取得は中間配列を作らないfindへ変更。
- 将来の大射程や異常な旧保存に備え、攻撃／危険範囲の走査を盤面内に限定。射程10億のモデル試験でも盤面外ループを生まない。
- 後続のrequestAnimationFrame内で描画例外が起きると、演出Promiseが未解決のまま操作ロックが残り得た。例外をrejectし、rAFと代替タイマーの両方を解除する。実際に後続フレームで描画を失敗させ、確定済み状態への復帰とロック解除を確認した。
- 今後のマップ編集で行幅、未知地形、配置の重複、壁上配置、孤立した勝利地点を持ち込まない検査を追加。

描画にルール解決を混ぜず、observerの移動→攻撃→反撃→回復の順は保つ。追加演出は `playback.js` の表示用イベントと `view` の補間へ足す。常時のrAFループや大量パーティクルは足さず、動いているイベントの間だけ描く。通常／高速／動きを減らす設定と最終結果の同一性も維持した。

## FE系の操作感との対応

比較したのは操作と情報の流れ。四方向の地形コスト付き移動、味方通過と敵の占有、1部隊1行動、未行動巡回、移動域と攻撃域の区別、先に読むダメージ・反撃・残HP、敵一隊ずつの移動と交互の攻撃を維持している。タップ移動と連続スライドの両方を用意し、盤面外の固定欄で指や窓が戦場を隠さない。

トラキア／GBA作品／Heroesは細則が異なるため、全作品と同じルールとは扱わない。この作品の100%命中、追撃・必殺・武器相性なし、4フェーズと有限P3支援は既存の独自設計。P3準備時の反撃放棄、弓の隣接不可、クラシックの離脱継承は説明・予測・実解決を対応させた。今後これらのルールを足す場合も予測と解決を同時に設計する。

## 配色と読み取り

盤面の青・赤・緑と分け、インターフェースを紫がかったチャコール、アイボリー、くすんだ金へ統一。攻撃の主要ボタンは金、待機は落ち着いた紫。固定欄、モーダル、ヘッダ、フッタ、表示ツール、OSテーマ色を揃えた。半透明は残し、背景ぼかしの合成を外す。能力値・予測は14px、操作対象44px以上、固定欄の高さを保つ。
