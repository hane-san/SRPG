# 戦線指揮 — FIELD COMMAND

スマートフォン縦画面で遊ぶ、決定論のオリジナルSRPGプロトタイプ。4フェーズ、有限の戦術スキル、動かずに行う援護・回復、連戦での永久離脱を試します。FEに着想を得ていますが、画像・音楽・キャラクター・コードは流用していません。

**テストプレイ**：https://hane-san.github.io/SRPG/ （公開・起動確認済み）  
**ソースの正本**：https://github.com/hane-san/SRPG  
現在の版：0.1.1。バージョンはメニューの「このゲーム・検証記録」に表示。

## はじめかた

メニューで3マップから選び「開始」。青い部隊 → 移動先 → 命令 → **この命令を確定**。「命令終了」で敵軍・待機支援・戦場イベントへ進みます。選択中の部隊の再タップ、または「解除」で選択を外せます。「取消」は移動先と命令の仮指定を戻します。

- 画面の地図は指で上下左右にスクロール。＋／−で3段階の地図倍率、右上の全体図で移動。「自軍へ」で戻る。
- 移動は命令を確定するまで反映されず、取消可能。敵をタップすると通常攻撃のダメージ・反撃を予測。部隊の「詳細」から能力値と保守的な被害上限を確認できます。
- 「危険域」は敵の移動後射程。「詳細」にある移動先の最大被害は各敵の単独到達を合算した保守的な上限。守備隊の行動制限や相互の進路妨害を省くので、予言ではありません。
- メニューでクラシック／カジュアル、敵火力、回復H0／H1／H2、「難易度・回復・スキル回数の設定」を開き、スキル回数1／初期値／4を変更して**新しい戦闘を開始**。進行中の数値は変わりません。
- 単体試験は毎回全隊が揃う。連戦はクラシックの離脱が次章へ残り、カジュアルは次章に復帰。HP・残回数は次章で回復。全軍4隊未満なら無名の予備隊を追加。
- 同じ端末・ブラウザではP1と勝敗確定状態を自動保存。クラウド同期・オンライン送信なし。再試行はその章の開始時の部隊構成へ戻る。版が変わると途中保存は引き継がない。
- 北城へ入れば勝利。南北挟撃では本陣に敵が入ると敗北、南城の制圧で増援停止。

iPhone Safari：共有 → ホーム画面に追加。Android Chrome：メニュー → ホーム画面に追加。ブラウザからそのまま遊べます。iOSの専用PNGアイコンは未制作のため、機種によってホーム画面の見た目は異なります。

## ルール

| フェーズ | 内容 |
|---|---|
| P1 味方 | 移動＋攻撃／スキル／守備、または移動せず待機支援を準備 |
| P2 敵軍 | 敵の移動・攻撃、射程が合う味方の反撃 |
| P3 支援 | 生存する味方の待機射撃・回復。射撃への反撃なし |
| P4 戦場 | 前ターンに予告した砲撃・増援、次の予告 |

待機支援中はP2に反撃しません。通常守備は被害−1、盾の堅守は−3（最初に被攻撃した時に1回分消費、当該ターンの攻撃すべてに有効）。援護射撃は射程2〜3。待機回復7・即時回復6。回復対象は自分以外。

支援の優先順：指定対象が射程内なら優先 → 射撃は撃破できる敵・攻撃力順／回復はHP割合が低い順 → 座標順。射撃の手動優先指定は敵移動後にも届く保証はありません。回復は欠損4以上から自動発動（指定時は閾値を無視）。温存ONなら有料の自動支援を停止。枯渇後の無料応急処置は継続。

ダメージ `max(1, 攻撃 + スキル補正 − 守備 − 地形 − 守備命令)`。命中100%、必殺・追撃・属性相性・射線遮蔽なし。森は移動コスト2・守備+1、砦は守備+1。砦の自動回復はありません。騎兵の「疾駆」は移動+2、敵や水域は通過できません。

## 3つの試験マップ

| マップ | 試す判断 | イベント |
|---|---|---|
| 霧河の渡し 12×20 | 正面の橋で連携／東の細橋へ騎兵を回す | なし |
| 二つの戦線 16×30 | 本陣防衛／北城速攻／南城を先に取る／東道へ別働隊 | T4・8・12…に南から1隊、南城制圧で停止 |
| 灰城の砲火 14×26 | 後衛警戒／回復のため停止するか砲撃から退避するか | 砲撃T3・6・9…、増援T4・8に各2隊 |

敵の出現位置は前ターンP4で確報、出現後は翌ターンP2から行動。砲撃は次のP1を丸ごと与えたうえで、予告の赤枠の全員に固定6ダメージ（敵にも当たる）。砲撃標的は予告時に最も南の味方、同率なら西側。増援地点の占有はその部隊の到着を中止します。

## 編集とローカル実行

Node.js 22以降、Python 3があれば動きます。実行時の依存パッケージはありません。

```sh
git clone https://github.com/hane-san/SRPG.git
cd SRPG
npm run dev
# http://localhost:4173
npm run check
npm run simulate
```

| ファイル | 主な編集内容 |
|---|---|
| `config.js` | HP・火力・射程・回数・回復量など |
| `data.js` | 3マップの地形・配置・目的地・増援位置・初期部隊 |
| `engine.js` | 移動・戦闘・敵AI・4フェーズ・勝敗の処理 |
| `app.js` / `style.css` | 命令UI・メニュー・連戦 |
| `ui-input.js` / `save.js` | タップとドラッグの判定・保存データの検証 |
| `render.js` | 手続き生成のオリジナル仮ドット絵・範囲・全体図 |
| `tests/` | ルール・ブラウザ・簡易方策の再現試験 |
| `docs/balance.md` | 採用理由・検証結果・残る問題 |
| `AGENTS.md` | Codex / Claude Code等への編集時の引継ぎ |

マップ座標は0始まり、UI表示は1始まり。スキル枠は兵種ごとに1つ。新規ルールを足す前に、配置と数値で調整します。

任意のブラウザテスト：

```sh
npm install --no-save playwright
npx playwright install chromium
# 別ターミナルで npm run dev
node tests/browser-check.mjs
node tests/interaction-check.mjs
```

`?debug=1` はテスト用の状態スナップショットを公開します。通常プレイには不要です。`test-results/` に検証画像と結果を出力（git対象外）。

## 公開・更新

GitHub Pagesは **Deploy from a branch / main / (root)** で公開済み。以後mainへのpushで更新されます。`.github/workflows/check.yml` はルールのCI検証です。Pages用のビルドツールは不要。

```sh
node scripts/release.mjs 0.1.1
npm run check
git add .
git commit -m "Tune SRPG balance"
git push origin main
```

リリーススクリプトがモジュール・CSSの更新パラメータを揃え、古いファイルとの混在を防ぎます。Service Workerの固定キャッシュはありません。メニューの「最新版を確認」から更新でき、Pagesの反映には待ち時間があります。コードを編集しただけで版を上げない運用は避けてください。

検証の根拠と限界は [仕様・バランス検討](docs/balance.md) を参照。iPhone/Android実機のOS固有操作やFPSは未計測です。
